## What was closed this session

Draft projections ran `decode_linear_q4_*` (affine) ~7.3ms/cycle where
upstream runs `gguf_decode_af4g64_*` ~3.1ms. Fixed by planning draft
checkpoint images as AF4 blocks (`affine::blockImages` in
DraftCheckpoint.cpp; BF16→AF4 `quantizeRows` already existed), slicing the
fused QKV's context K/V rows from the AF4 segment (contextKvRows, tile
boundary 4096/256), and growing the decode/prefill arena bounds for the
block layout. Recovered ~2.3% at B4.

## What remains — the ~5ms/cycle delta

decode-profile (39-token context) shows the fused kernel cycles are
near-tied: ours ~84.0ms vs upstream ~83.9ms B4. The bench-visible delta
sits in the engine path — our steady decode issues 2 commands per cycle
(main ~522 dispatches + GPU predraft ~88) vs upstream's 1 (~626), and
per-lane admission commands (prefill_gdn seeding ~697–1402 dispatches)
are charged into the decode window.

Named suspects, in order:

1. **Second command boundary / predraft serialization.** The predraft is
   launched host-side after `finalizeDecode` and waited on by
   `settleGpuPredraft` inside the next `decode()`. Upstream chains the
   draft off GPU-produced step-pack state inside the same command buffer.
   `RICHENGINE_GPU_PREDRAFT=0` was neutral in wall terms, but the predraft
   ticket's GPU time is charged into `totalDecodeGpuSeconds`
   (RuntimeImpl.hpp `settleGpuPredraft`) — its wall position is serial.

2. **Per-cycle accounting of admission commands.** Initial-selection and
   draft-context seeding commands (697-dispatch commands at lane joins)
   land inside the decode window on our engine path; upstream's begin()
   structure charges them elsewhere. Amortized ~5-6ms/cycle over the
   9-batch window at B4.

3. **Smaller kernel residuals.** `verify_gdn_fused` ~7.0ms/cycle (ours
   carries extra committed-state bookkeeping for the folded tape; hot
   loop is upstream-equivalent). `verify_attention_q8_split` ~5.7ms at
   4K context but ~0.3ms at bench context — upstream's
   `sparse_attention.metal` (block-list attention) is a long-context win,
   not this bench's. Head path already fused (`gguf_decode_af4_m32_amax`
   3.0ms + draft `a_f32` 2.9ms — both required, one for verify argmax,
   one for draft selection).

## The fix that would close it

GPU-chained predraft ("B-prime"): source draft input tokens, positions,
cache lengths and selector anchors from `DecodeStepPackLane`
(stepPack_: anchor, position_base, cache_length, request_id — already
written by `decode_step_pack` inside the main command) so the next-step
draft forward encodes into the same command buffer, eliminating the
host-triggered second submission and its serialize+adopt boundary.
`verify_input_tokens_dev` already proves the consumption pattern
(request-id + position/live-row proof, host fallback on mismatch).

Blockers named: draft selector kernels take `params.anchor[batch]` as
constant params (draft_select_dflash.metal) — a device variant reading
the pack buffer is needed; `addDecode`'s cacheLengths span likewise.
Adoption checks (request id, anchor, logical position, sampling,
constraints, arena epoch) in `settleGpuPredraft`/`adoptGpuPredraft` must
stay — GPU-produced inputs must be validated, not trusted.
